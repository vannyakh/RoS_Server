# Gameplay function audit

**22 November 2026 · server revision `b35d7ec`.** Two authenticated JSON clients can fight in the same match and read the resulting account totals. The original Android gateway creates a separate battle object for each remote address. A player reaching a map through that gateway does not establish that two players share the map or that a victory reaches storage.

The installed original Android game was in the foreground at **“Retrieving patch lists 0.00%”**. That is one direct screen observation. It establishes the launch stage reached during this audit, without identifying the cause. The November 19–21 emulator observations cover later stages on earlier runs. The table for the original game below accounts for those observations. [Device evidence](ANDROID_IOS_COMPATIBILITY.md) · [Execution record and 22-step test](GAMEPLAY_TEST_PLAN.md)

**Status applies to the function and path named in each row.** Working requires an executed check of that behavior. Partial means some of the requested behavior exists. Missing means the inspected path has no implementation. Untested means executable code exists without a confirming check. Blocked identifies an external prerequisite. None of these labels changes the project's original-client compatibility matrix.
